## Shaolin Scroll Release Details

Shaolin Scroll releases now have standalone, database-driven detail pages at:

`/mark2/shaolin-scrolls/[id]`

### What Changed

- Replaced the release dialog with a full server-rendered detail page.
- Release links now use normal navigation instead of opening a modal.
- Added release-specific metadata and canonical URLs.
- Added a release summary containing:
  - Release name
  - Semantic version
  - Release type
  - Status
  - Official release date
  - Activity-window start and end dates
  - Release-window length
  - In-progress status when applicable
- Added conditional activity sections that only appear when matching activity exists.

### Release Activity Windows

Release windows are calculated by the database.

For completed releases:

- Start: the day after the previous completed release
- End: the current release date, inclusive

For an in-progress release:

- Start: the day after the latest completed release
- End: today

For the earliest release, the start is derived from the earliest meaningful activity available on or before that release.

### Supported Activity

Release details currently summarize:

- Chronicles
- Chronicle amendments
- TCDb trades sent
- TCDb trades received
- LCS visits
- USPS visits
- Reviews
- Bricks build sessions
- Set Collector snapshots

Chronicle amendments are treated independently from original publication dates. An amendment to an older Chronicle can therefore appear in a newer release without reclassifying the Chronicle itself.

### Database Architecture

The implementation adds three reusable views:

- `dojo.v_shaolin_site_activity`
- `dojo.v_shaolin_release_window`
- `dojo.v_shaolin_release_activity`

These views normalize meaningful dated activity while excluding generic audit timestamps, authentication activity, migrations, and incidental row maintenance.

Historical release activity remains dynamic. Corrections and backfills to source data will automatically update the corresponding release detail.

### Cleanup

The previous dialog architecture was removed, including:

- `ScrollDialog`
- `useScrollDialog`
- Dialog-specific client routing
- The obsolete Shaolin Scroll detail API
- Dialog-focused tests
- Deep-link dialog documentation

Shared dialog primitives remain because other site features still use them.
